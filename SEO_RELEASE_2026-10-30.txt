Подготовка SEO-релиза 30.10.2026

Причины 31 ошибки исходного HTML:
— 27 товарных URL Новокузнецка возвращают 404 product.php и отсутствуют в дереве разделов. Добавлены в перепроверяемый список снятых товаров. При восстановлении карточки она возвращается в manifest.
— Два реальных раздела солнцезащитных очков для мальчиков существуют, но пока пусты. Они сохраняются с корректным заголовком, сообщением об отсутствии товаров и ссылкой на категорию.
— Старый URL /catalog_s/solntsezashchitnye_ochki/detskie_1/dlya_malchikov_/ перенаправляется 301 на фактический раздел /catalog_s/solntsezashchitnye_ochki/detskie_/dlya_malchikov_/.
— Раздел /catalog_s/linzy_dlya_ochkov/prizmaticheskie/ отсутствует в дереве API. Исключается из sitemap после проверки дерева; при восстановлении раздела возвращается.

Маршрутизатор проверяет существование пустого раздела по catalog_sections.php. Отсутствующая карточка больше не превращается в успешную страницу пустого каталога. Ошибка API не считается доказательством отсутствия раздела.

В @tanstack/start-plugin-core 1.171.17 исправлены повторные попытки и передача окончательной ошибки из очереди. Патч закреплён через Bun patchedDependencies, без смены версии библиотеки. Регрессионные тесты проверяют HTTP 503, обрыв соединения и исчерпание трёх попыток. Полная проверка Apache теперь включает все снятые товарные URL и разделы.

Подготовка кандидата использует штатный workflow Prepare production candidate: полный manifest, сборка всех страниц, проверки HTML, упаковка с SHA-256, изолированная проверка Apache, редиректы и откат. Фактический backend сверяется с manifest текущего frontend-релиза, поскольку отдельная старая запись backend-релиза устарела. На момент начала проверки все зависимости текущего frontend-релиза совпали с production; SHA backend 055815132220d0b2fde1a3c0f7b9da7fea5a6528.

Публикация production не выполняется. Legacy-корень beta нельзя заменять старым сценарием SPA-деплоя. Robots.txt сохраняет текущую production-политику, включая ограничение /catalog_n/*; данный пакет не меняет решение об индексации городов. Полное покрытие всего активного ассортимента остаётся отдельной задачей.

Окончательные результаты полной приёмки и ссылка на упакованный кандидат фиксируются в PR после завершения workflow.
