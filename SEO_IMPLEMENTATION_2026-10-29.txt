Первый пакет SEO после перехода на React-витрину

Изменения
1. Meta description карточек: сохраняется непустое description; иначе используется обычный текст descriptionHtml с декодированием HTML-сущностей, удалением разметки и ограничением длины. Если оба источника пусты, используется имя товара без обещания наличия. Одинаковое правило для description и og:description во всех товарных маршрутах.
2. Данные списков больше не заполняют кеш полной карточки. Прямой вход и переход из каталога получают подробности из product.php. Подтверждённый пример: у as_stellest_2_0_crizal_prevencia в списке HTML-описания нет, в полном API оно есть.
3. Названия разделов учитывают родительскую категорию. Исправлены детские оправы, оправы для мальчиков/девочек, детские очковые линзы и подразделы солнцезащитных очков. Метаданные подразделов используют эти же названия; Новокузнецк не наследует петербургское описание. Редакционные тексты цветных и мультифокальных контактных линз сохранены.
4. Production prerender прекращается при ошибках загрузки товара или каталога. Проверка артефакта отклоняет каталог без H1, содержимого main, непустого description, а также страницы с сообщениями об ошибке загрузки.
5. Beta-сборка формирует одиннадцать контрольных страниц с проверкой исходного H1 и description, включая MiYOSMART, Stellest и недоступную в списках оправу NOMAD.
6. В manifest включены 98 проверенных адресов из GSC и внутренних ссылок, независимо от фильтра наличия в листингах. На каждой сборке они повторно проверяются через product.php. Все 82 успешных URL исторической noindex-группы и все 240 успешных URL crawled-группы теперь покрыты manifest; два исторических 404 остаются исключены.
7. Перепроверяются 290 устаревших адресов: в Битриксе у 81 элемента ACTIVE=N, для 209 нет элемента. Они исключаются из manifest/sitemap только при повторном 404 API; восстановленный товар возвращается, даже если inStock=false. Ошибка API останавливает сборку. Устаревшая товарная ссылка в статье Varilux заменена на раздел прогрессивных линз.
8. Beta-сборка формирует index.html родительских разделов оправ и линз. Иначе новые вложенные примеры создают физические директории, которые старая beta-маршрутизация пропускает без SPA fallback и отвечает 403.

Проверка
TypeScript: успешно. Основные тесты: 66/66; unit: 48/48. ESLint: 0 ошибок, 20 существующих предупреждений. Десять проверок исходного HTML выполнены также через защищённый изолированный beta-preview. Проверены мобильные заголовки, description/og:description MiYOSMART и Stellest после загрузки JavaScript и город Новокузнецк. Корень beta содержит legacy-копию: попытка обычного SPA-деплоя автоматически откачена, исходный .htaccess совпал с резервной копией по SHA-256. Полная production-проверка обязательна перед публикацией; статус выпуска отражается в PR.

Границы пакета
Полный запуск build:production выявил обрыв соединения на двух карточках. В установленном @tanstack/start-plugin-core 1.171.17 повторная постановка страницы в очередь блокируется набором seen; итоговая проверка правильно отклонила неполный артефакт. Для проверки HTML страницы повторно отрендерены тем же скомпилированным сервером. Это не считается чистым прохождением build:production. До выпуска нужно исправить повторные попытки и повторить воспроизводимую сборку. Во время повторного получения manifest состав живого каталога вырос с 8 950 до 9 036 URL; источник данных и артефакт также требуют согласованного снимка.

Robots, canonical, noindex и production-маршрутизация не изменяются этим пакетом. Manifest/sitemap уточняются по проверенным действительным и удалённым URL. Публичный sitemap сейчас действительно отдаётся из активного frontend-релиза: его SHA-256 совпал с файлом релиза, в отличие от конфликта robots. Новые проверки содержимого относятся ко всем URL manifest, но не доказывают полноту всего активного ассортимента.

Оставшаяся проблема покрытия
products.php специально исключает CATALOG_AVAILABLE=N. При этом прямой product.php и PHP fallback принимают ACTIVE=Y, включая отсутствующие товары. Проверка Bitrix 29.10.2026: инфоблок 7 — 12 588 активных, из них 2 127 доступных; инфоблок 2 — 11 388 активных, из них 2 070 доступных. Поэтому обход листингов не обеспечивает полный HTML для всех прямых URL. Нельзя исправить это увеличением лимита страниц либо произвольным удалением noindex.

Добавленный проверяемый список закрывает известные адреса GSC, но не заменяет источник полного перечня действительных канонических карточек. Следующий отдельный пакет: такой источник, стратегия серверного HTML/обновления всех карточек и явное поведение для отсутствующих товаров. До этого production fallback остаётся оболочкой для прочих URL вне сборки. Открытие robots Новокузнецка и изменение политики индексации требуют отдельного проверенного артефакта и выпуска.

Итог расширенной приёмки
Все 98 специально включённых карточек прошли проверку исходного HTML, включая 77 отсутствующих в наличии. Проверка файлов и внутренних ссылок охватила 9 036 URL, но итоговая проверка содержимого отклонила артефакт: 31 URL содержит состояние недоступного раздела. Также выявлены 79 ошибок description в явном маршруте Новокузнецка; этот маршрут исправлен и добавлен в контрольные beta-страницы. Для выпуска требуется новая полная сборка после устранения оставшихся ошибок. Неполный артефакт не публиковался.
