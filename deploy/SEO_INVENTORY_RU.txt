Полнота sitemap и источник канонических URL

Источником списка товаров является полный снимок Bitrix ACTIVE=Y по инфоблокам Санкт-Петербурга и Новокузнецка. Фильтр CATALOG_AVAILABLE не применяется: отсутствие на складе не означает удаление карточки. Путь определяется основной секцией и её предками через тот же o_catalog_identity(), который использует product API.

Перед каждым production-кандидатом обновить снимок чтением по SSH:
node scripts/refresh-seo-inventory.mjs --host USER@HOST --identity PATH_TO_KEY

Экспортёр работает только в CLI, не устанавливает HTTP endpoint и не меняет каталог. Снимок содержит ID, город, canonicalPath, наличие и активность цепочки разделов; без цен, персональных данных и секретов. Снимок необходимо проверить и закоммитить до запуска Prepare production candidate. Сборка блокируется при возрасте снимка больше 48 часов, расхождении количества, дублировании идентичности или некорректном пути.

При изменениях дерева/активности каталога между проверкой и публикацией нужен свежий снимок и новая полная сборка. Снимок не заменяет регулярное обновление статической витрины: новые товары появляются в sitemap после следующего выпуска. Автоматизация обновлений требует отдельной настройки доверенного доступа к источнику, а не секрета в публичном репозитории.

Перед сборкой проверить node scripts/reconcile-canonical-redirects.mjs. При ненулевых changes изучить результат; режим --write обновляет redirects.production.txt. Старый редирект VX с пробелом снят; оба адреса получают 200 и canonical полного пути, без обратного редиректа и цикла в браузерах с закешированным 301. Активный канонический URL не должен быть источником редиректа. Alias с ответом 200 получает canonical из API, а не из запрошенного пути.

По согласованию 30.10.2026 снят общий запрет robots для /catalog_n/ в группах * и Yandex. Индивидуальные запреты, включая Stellest, сохранены. Неактивные разделы и их товары не добавляются в sitemap. Снятые товары сохраняют ранее проверенные 404.

Prepare production candidate проверяет все страницы, ID товара и canonical в исходном HTML, отсутствие ошибок/noindex, ссылки, XML sitemap и полноту относительно снимка. Apache проверяет весь готовый пакет и редиректы, включая query и кодирование пробела, плюс откат. generated/seo-coverage.json и inventorySha256 в release-manifest.json связывают результат со снимком. Публикация выполняется отдельным шагом после проверки кандидата.
