Автоматическое обновление каталога и sitemap

Контроллер: scripts/run-catalog-refresh.mjs. Планировщик Codex вызывает один шаг каждые 15 минут; проверка изменений каталога запускается раз в 6 часов. Незавершённая GitHub-сборка проверяется на очередном шаге. Для выполнения нужен включённый компьютер с Codex, локальным SSH-ключом и авторизацией gh. Секреты production в GitHub не передаются. Пропущенные запуски выполняются после возвращения компьютера в сеть, строгого SLA нет.

Контроллер и конфигурация привязаны к проверенному sourceSha. Изменения приложения автоматически не подхватываются. Каждый обновлённый снимок оформляется отдельным коммитом в automation/catalog-refresh-*, на базе проверенного исходного кода; main и рабочая ветка пользователя не меняются. GitHub выполняет существующий Prepare production candidate: тесты, TypeScript, lint, полный prerender, проверку HTML/canonical/sitemap, Apache всех маршрутов и репетицию отката. В production отправляется именно этот архив с проверенным SHA256.

Полный read-only экспорт Bitrix включает ACTIVE=Y без фильтра наличия и хеши источников контента: поля/свойства товаров, секции, цены, остатки, изображения, справочники, SKU и скидки. Исходные значения таблиц не экспортируются. Время создания снимка не считается изменением. При неизменном снимке выпуск пропускается; контрольная полная пересборка выполняется не реже раза в сутки для зависимостей, не отражённых в снимке. Проверка таймера происходит при очередном шестичасовом опросе.

Защита
— Локальная блокировка контроллера и серверный flock не допускают параллельного переключения.
— SHA frontend, backend, routing и контрольные суммы всех production-файлов должны совпадать с записанным состоянием. Другой ручной выпуск останавливает автоматизацию до согласованного обновления базы.
— Сокращение активных товаров в действующих разделах более чем на 2% хотя бы в одном регионе блокирует выпуск для проверки импорта.
— Каталог повторно экспортируется после сборки и после загрузки; любое расхождение отменяет публикацию. В приёмке после переключения он проверяется ещё раз под release lock. Если источник продолжает меняться, требуется повторить сборку после завершения импорта.
— Проверяются checksum публичных robots/sitemap, контрольные HTML-страницы обоих регионов, прежние обязательные адреса, снятые URL, frontend/backend-файлы и штатный smoke корзины/order/auth/CSRF. Ошибка приёмки автоматически возвращает предыдущие HTML/sitemap/robots/routing. База данных не откатывается.
— Старый физический public_html/robots.txt запрещён: он перекрывает файл релиза в Nginx.
— Сохраняются текущий и предыдущий серверные релизы. Удаляются только более старые версии, для которых есть проверенный локальный архив и совпадающий манифест; файлы неожиданно изменённой версии не удаляются. Артефакты GitHub дополнительно сохраняются 30 дней. Локальные архивы автоматически не удаляются.
— Ошибка оставляет halted=true и JSON-отчёт. Повторная публикация не выполняется вслепую. Незавершённое переключение восстанавливается по фактической серверной транзакции; новый frontend другого выпуска не откатывается.

Конфигурация и state.json хранятся вне Git в outputs/catalog_refresh_2026-10-30/automation. В конфигурации только путь к SSH-ключу, не сам ключ. Запуск без --execute выполняет read-only проверку; с --execute запускает следующий разрешённый шаг. Отчёты, архивы, снимки и ссылки на GitHub сохраняются в runs/<timestamp>/.

После ошибки: прочитать last-result.json, state.json и журнал текущего runs/<timestamp>; подтвердить фактический frontend, backend и routing. Для проваленной сборки очистить pending только после сохранения причины; для прерванного deploy сначала проверить active-transaction/status и штатный rollback. Обновлять sourceSha и базу разрешено после проверки нового кода/ручного релиза. Для остановки выключить heartbeat в Codex; уже запущенный GitHub-кандидат сам по себе production не меняет.

Проверенная техническая доступность не означает индексацию Google. GSC проверяется отдельно SEO-специалистом. Контроллер не создаёт заказов и не отправляет сообщения сотрудникам.
