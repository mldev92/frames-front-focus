Уточнённое техническое задание для каталога оправ Оптики 100%
Проверка от 6 ноября 2026 года

Цель

Дополнить женский каталог полезной информацией и навигацией, создать первую самостоятельную страницу бренда и улучшать существующий поиск. Сохранить работающий каталог, фильтры, карточки, покупку и интеграцию с Bitrix. Внедрение выполнять по этапам с локальной проверкой и отдельным выпуском на production.

Основание

Исходное ТЗ: optika100_TZ_zhenskie_opravy_poisk_brendy_tehdorabotki.docx.
Проверены исходный HTML production, API products.php v2 и актуальный frontend checkout d625b35.
Прототип https://eyes-your-way.lovable.app/ при прямом запросе вернул 403. Визуальное соответствие прототипу не подтверждено; текстовые требования взяты из переданного документа. Прототип не заменяет данные каталога и существующую дизайн-систему.

Результат проверки исходного ТЗ

1. Развёрнутый полезный контент, FAQ, доступные HTML-ссылки, самостоятельная страница бренда, canonical и согласованность данных нужны. Эти направления сохраняются.

2. Числа в исходном ТЗ нельзя использовать как актуальные. В нём одновременно фигурируют 607 и 832 позиции, разные количества ANA HICKMANN и разные количества форм. API на момент проверки вернул 790 женских позиций, 89 брендов, диапазон цен 1 900–35 870 руб. Для LION`S HEART в общем каталоге получены 69 позиций, в том числе 41 женская и 28 мужских, диапазон 3 800–8 070 руб. Это контрольный снимок, а не значения для хардкода. API считает позиции каталога; уникальность модели независимо от цвета и артикула отдельно не подтверждена.

3. Исходный HTML женского каталога содержит прежний H1, метаданные и 0 H2. Каталог работает через prerender и последующую React-гидратацию. На момент проверки числа из опубликованной страницы и текущего API различаются. Новые числа должны попадать в HTML при сборке из того же API, что обслуживает каталог. Период обновления HTML необходимо согласовать с действующим процессом обновления каталога; одна локальная правка не обеспечивает постоянную актуальность опубликованного снимка.

4. Утверждение «без SSR Google не проиндексирует» неверно. Google обрабатывает JavaScript, но серверный или предварительно сформированный HTML улучшает доступность и уменьшает зависимость от рендеринга. Для проекта сохраняется практическое требование: полезный текст, заголовки, FAQ, ссылки и JSON-LD должны присутствовать в готовом HTML без выполнения JavaScript. Переписывать действующий prerender на отдельный SSR-сервер не требуется.

5. FAQ полезен посетителям. Однако Google прекратил показ FAQ rich results с 7 мая 2026 года и удалил документацию в июне. Добавление FAQPage не является P0 и не обещает расширенный сниппет. Существующую разметку других страниц в рамках этой задачи не удаляем.

6. Для списка товаров используем ItemList и BreadcrumbList. Не выдаём много разных товаров категории за одну страницу Product ради расширенного результата. Разметку Product/Offer проверяем отдельно на карточке конкретного товара. JSON-LD должен описывать реально показанные карточки, цены и наличие, без выдуманных рейтингов и офферов.

7. Поиск уже существует: ссылка в шапке ведёт на /search/, есть товарная выдача и поиск по страницам, услугам, категориям и статьям. Требуется расширение этого механизма: autocomplete и словарь альтернативных написаний, а не создание второго независимого поиска. Наличие существующего поиска не означает, что требования к подсказкам уже выполнены.

8. Отдельная страница /catalog_s/opravy/lions-heart/ относится ко всему ассортименту этого бренда. Поэтому её хлебные крошки: Главная → Оправы → LION’S HEART. Число женских позиций не выдаётся за полный ассортимент бренда. Детская марка LION`S HEART ДЕТСКИЕ не объединяется автоматически с LION`S HEART. Ссылка из женского каталога явно объясняет переход к полному ассортименту бренда.

9. «В каталоге» и «в наличии именно в салоне» имеют разный смысл. Не используем общее число каталога в бейдже наличия в салоне. Возможность примерки, резервирования и заказа уточняется по конкретной позиции. Не подменяем покупку единственной кнопкой записи на примерку.

10. Убираем неподтверждённые обещания: «титан самый лёгкий и гипоаллергенный», «не давит», «линзы подходят почти в любую оправу», «все модели подходят для прогрессивных линз», «бесплатный подбор специалистом». Рекомендации по форме лица оставляем ориентиром для примерки. Бесплатная примерка и платный профессиональный подбор не смешиваются; обещания бесплатности публикуются только после подтверждения условий салоном. Прогрессивные линзы подбираются с учётом конкретной оправы и рецепта.

11. Числа 46–61 мм относятся к ширине линзы, а не к общей ширине оправы. Не сокращаем существующие фильтры до искусственных диапазонов 46–57 мм и не исключаем реальные цвета, материалы или формы из базы. Сумма значений фасета не обязана совпадать с общим числом позиций: возможны несколько значений и незаполненные характеристики.

12. Число H2 у конкурентов и доля конкурентов с FAQ не подтверждены списком URL и датой проверки. Не используем их как обязательную норму. Уникальные метаданные помогают различать страницы, но сами по себе не доказывают и не устраняют каннибализацию: для её оценки нужны запросы, посадочные, показы и клики Search Console/Яндекс Вебмастера.

Этап P0 Женский каталог

Адрес: /catalog_s/opravy/zhenskie/.
H1: Женские оправы для очков.
Title: Женские оправы для очков в Санкт-Петербурге — Оптика 100%.
Description: Женские оправы для очков в Санкт-Петербурге: кошачий глаз, бабочка, прямоугольные модели. Фильтры по бренду, форме, материалу и цене. Примерка на Кирочной, 17.
Open Graph использует соответствующие заголовок и описание. Canonical сохраняет существующий адрес раздела. В метаданные не включаем быстро меняющиеся счётчики и минимальную цену.

Над каталогом: хлебные крошки, один H1, короткое введение, счётчик позиций и брендов, диапазон цен из API, переход к товарам и к подбору оправы. Сохраняем компактный первый экран и быстрый доступ к фильтрам и товарам на ширине 375 px.

После каталога: список брендов с количеством женских позиций и локальным поиском, формы и материалы с фильтрующими ссылками, пояснения по размерам и рецепту, ценам и наличию, FAQ, связанные разделы и контакт салона.

Счётчики описывают весь женский раздел. При применении фильтра счётчик выдачи каталога меняется, а справочные числа раздела сохраняют исходную область. Нельзя считать общую минимальную цену по первой странице из 24 товаров. Для дополнительных фильтров загружаем отдельный итоговый снимок раздела; не используем drill-down-фасеты отфильтрованной выдачи как статистику всего раздела.

Все ссылки на бренды должны находиться в HTML. Свёрнутый блок «Все бренды» допустим: его ссылки остаются в HTML, а поиск работает поверх доступного списка. Для брендов без самостоятельной страницы ссылка ведёт на существующий женский каталог с brand-параметром. Это навигационные фильтры, а не отдельные утверждённые индексируемые бренд-лендинги. Не добавляем все комбинации фильтров в sitemap.

FAQ отвечает на выбор оправы, форму для круглого лица, цены, совместимость оправы и линз, прогрессивные линзы и адрес примерки. Отказываться от уже работающей покупки, скидок и характеристик карточек не требуется.

Адрес: /catalog_s/opravy/lions-heart/.
H1: Оправы LION’S HEART в Санкт-Петербурге.
Title совпадает с H1 и дополнен названием Оптика 100%.
Description: Мужские и женские оправы LION’S HEART в Санкт-Петербурге. Сравните цены, формы, материалы и размеры в каталоге. Примерка и подбор в салоне на Кирочной, 17.

Фиксированный фильтр API: category=opravy, brand=LION`S HEART, city=spb. Параметр brand в URL не может заменить фиксированный бренд. Остальные фильтры, цены, сортировка и пагинация продолжают работать. Собственный фильтр смены бренда здесь скрыт. Карточки ведут на существующие товарные адреса, без нового пространства дублирующих брендовых карточек.

Добавляем self-canonical, видимые хлебные крошки и BreadcrumbList, ItemList показанных карточек, введение, фактические характеристики, FAQ и ссылки на общий/женский каталог, подбор и прогрессивные линзы. Не приписываем всему бренду свойства отдельных моделей. Страница включается в production manifest, sitemap и предварительную генерацию HTML.

Этап P1 Развитие поиска

Расширить действующий поиск в шапке до поля с подсказками по брендам, товарам и страницам/категориям. Сохранить отдельную страницу результатов и noindex служебной выдачи.

Для подсказок: задержка ввода 200–300 мс, отмена прежних запросов или защита от устаревших ответов, клавиатурное управление, Enter, Escape, корректные ARIA-состояния, состояния загрузки и отсутствия результатов. Проверить мобильную шапку. Использовать существующий товарный API и индекс страниц, не выводить полный каталог в браузер ради поиска.

Кириллица и латиница поддерживаются проверенным словарём брендов и продуктовых линеек. Это не обещание автоматической транслитерации любого названия. Локальный фильтр брендов уже может использовать такие варианты, как Guess/Гесс, LION’S HEART/Лайонс Харт, Silhouette/Силуэт, Stepper/Степпер. Отдельно добавить и проверить Stellest/Стеллест в общем поиске товаров и страниц.

Этап P1 Остальные бренды

Выбирать следующие страницы по реальному ассортименту и поисковому спросу. GUESS, Silhouette, Stepper, Carrera и Hugo/Hugo Boss — кандидаты, а не автоматически утверждённый список. Hugo, BOSS и HUGO BOSS не объединять без проверки классификации каталога.

Для каждой страницы нужны стабильный адрес без конфликта с существующими URL, самостоятельная польза, достаточный ассортимент, корректная область бренда, фактический текст, внутренние ссылки, self-canonical и включение в sitemap. Не создавать десятки пустых страниц заменой одного названия в общем шаблоне.

Этап P2 Остальные категории и измерение результата

Проверить мужскую, детскую и общую страницы по запросам и данным вебмастеров. Развести интенты и контент по результатам анализа. Добавить уместные взаимные ссылки, не дожидаясь P2 для уже выпускаемых женской и брендовой страниц.

Зафиксировать до выпуска посадочные, поисковые запросы, показы, клики, CTR, позиции и доступные конверсии. Проверять результат после переобхода и накопления данных; не обещать рост позиций только от количества заголовков или объёма текста.

Критерии приёмки

1. Готовый HTML обеих страниц содержит один H1, введение, соответствующие разделы, полный FAQ и внутренние ссылки без запуска JS. Данные не заменены fixtures.
2. У обеих страниц правильные Title, Description, Open Graph и абсолютный canonical. В production отсутствует случайный noindex. /search/ остаётся служебной noindex-страницей.
3. BreadcrumbList соответствует видимым хлебным крошкам. ItemList соответствует показанным товарам и корректной позиции в пагинации. JSON корректен, товарные строки не могут закрыть script-тег.
4. Итоги и цены совпадают с одной областью API и имеют одинаковый смысл в интро, тексте и ссылках. Проверены нулевая выдача, фильтр бренда, фильтр материала, цена и вторая страница. Пустые и некорректные цены не превращаются в обещание «от 0 руб.».
5. На брендовой странице нельзя получить чужой бренд через URL или сброс фильтра. Женский фильтр на брендовой странице показывает только женские позиции этого бренда.
6. Локальный поиск брендов регистронезависим, поддерживает утверждённые алиасы, сохраняет количества и показывает понятное пустое состояние. Исходный HTML сохраняет ссылки всех брендов.
7. На 375 px и desktop нет горизонтального переполнения, каталог и CTA доступны, карточки открываются, FAQ раскрывается, фильтры работают. Нет ошибок гидратации и новых JS-ошибок.
8. Проверены TypeScript, применимые тесты, production prerender обеих страниц и готовый HTML. Ограниченная сборка двух маршрутов не заменяет полный release candidate и штатные проверки перед выпуском.
9. Выпуск выполняется отдельной операцией через утверждённый production workflow. После выпуска проверяются https://optika100.com, фактический HTML, мобильная/desktop-вёрстка, товарные переходы, canonical, sitemap и наблюдение по release runbook. Этот этап не означает разрешение на production-деплой в текущем запросе.

Статус первого пакета реализации

Подготовлен локально в отдельной ветке codex/seo-womens-20261106: женский контент, фактические счётчики, поиск по брендам с алиасами, ссылки форм и материалов, FAQ, связанные страницы, LION’S HEART, метаданные, BreadcrumbList, ItemList и включение брендового адреса в manifest. В существующий индекс поиска добавлены женский каталог и брендовая страница.

Для фильтрующих параметров двух посадочных добавлено адресное правило production.htaccess: загружается штатный SPA shell вместо неподходящего статического снимка без фильтра. Чистые адреса и адреса только с utm-параметрами продолжают отдавать SEO HTML. Это устраняет выявленную при прямом входе ошибку гидратации. Локально проверены правило, настоящий API, фильтр GUESS, женский фильтр LION’S HEART и попытка подменить бренд через URL. Нативный Apache и полный production release candidate проверяются штатным процессом перед выпуском.

TypeScript, 33 unit-теста и 22 проверки SEO/маршрутизации пройдены; production prerender обеих страниц завершён. Браузерная проверка чистых страниц на 375 px и desktop, поиска по кириллическому алиасу и прямых фильтрующих адресов пройдена без ошибок страницы. В общем наборе отдельно остаются прежний провал проверки заголовка меню контактных линз и проверка backend-файлов, зависящая от вложенного расположения checkout. Они не считаются закрытыми этим пакетом.

Глобальный поиск с autocomplete дополнительно выполнен локально: группы брендов, моделей и страниц/категорий, управление клавиатурой, задержка ввода 250 мс, отмена устаревших запросов, обработка частичных ошибок, региональные ссылки и единые алиасы, включая Гесс/GUESS и Стеллест/Stellest. Полная выдача остаётся noindex и использует тот же город. Очковые линзы берутся из актуальной базы подборщика через lens_search.php, без устаревших цен Bitrix; переход открывает поиск по этой базе в действующем каталоге. Перезагрузка /search/ с запросом использует штатный SPA shell перед выбором статического пустого снимка.

Остальные самостоятельные брендовые страницы, анализ каннибализации по данным вебмастеров и постоянная синхронизация опубликованного HTML с каталогом остаются следующими этапами. Изменения на production не публиковались.
