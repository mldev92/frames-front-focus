# Выпуск и откат React

React-витрина уже работает на production `https://optika100.com`. Production —
текущая цель выпуска и проверки. Beta больше не является обязательным этапом:
`deploy_beta.ps1` запускается только по прямому запросу пользователя на beta.

## Подготовка

1. Развернуть совместимые API отдельным пакетом backend. Сохранить манифест `.o100-backend-release.json` вне document root и резервную копию исходных файлов. Дождаться успешного HTTP smoke и проверки очереди.
2. Проверить фактический root `/home/t/tretya9f/wpoptik/public_html`, SHA256 `.htaccess`, HTTPS/www, PHP, API, авторизацию, callback оплаты и 1С. Изменение базовой конфигурации требует новой репетиции.
3. Запустить `Prepare production candidate` для опубликованного SHA, указав проверенные backend SHA и routing SHA256. Полный каталог собирается без ограничения маршрутов. При изменении каталога повторить подготовку, обновить sitemap и все prerender-страницы; частичное копирование HTML не использовать. Новый набор контента оформляется новым коммитом/кандидатом.
4. Скачать артефакт `production-candidate`: архив, SHA256 и манифест. Проверить его на защищённом Apache с тем же baseline и нативными путями. Записать идентификатор workflow run и контрольную сумму архива.
5. Выполнить приёмку сотрудниками из backend `FRONTEND_CUTOVER_IMPLEMENTATION_2026-10-18.md`, включая Safari/iPhone и Chrome/Android. Условия платежа: менеджер подтверждает заказ и выдаёт ссылку. Статус доставки «уточняется» не равен нулю.

## Согласование и переключение

Владелец согласует frontend SHA, backend SHA, workflow run ID, SHA256 архива, SHA256 live `.htaccess`, время и ответственного. Секреты `PRODUCTION_SSH_HOST`, `PRODUCTION_SSH_USER`, `PRODUCTION_ROOT`, `PRODUCTION_SSH_KEY`, `PRODUCTION_KNOWN_HOSTS` должны быть настроены. Known hosts заполняется из ранее проверенного ключа, не из сетевого keyscan перед запуском. Окружение GitHub `production` должно требовать ручное согласование.

Workflow `Deploy production` получает уже проверенный архив, не пересобирает его. Перед переключением сверяются все API и файлы артефакта. `deploy/release.sh` блокирует параллельный выпуск, сохраняет настоящие htaccess/указатель и родительскую транзакцию, атомарно переключает выпуск, запускает smoke. Ошибка вызывает восстановление предыдущего состояния, включая самый первый переход с legacy.

## Откат

Запустить `Rollback production`, указав frontend SHA инструмента развёрнутого выпуска. Либо в каталоге загруженных инструментов:

```sh
O100_SMOKE_ORIGIN=https://optika100.com bash deploy/release.sh rollback /home/t/tretya9f/wpoptik/public_html
```

Откат восстанавливает htaccess и прежний release pointer. Первый выпуск возвращается к legacy без pointer; последующий — к предыдущему React. Успешный откат возвращает родительскую транзакцию в active-transaction. Каталоги предыдущих релизов и хешированные `/assets/` сохраняются для открытых вкладок. База данных, совместимые API, очередь уведомлений и реестр попыток не откатываются.

При SIGKILL/отказе сервера сверить `.o100-deploy/active-transaction`, `transactions/*/status`, `htaccess`, `previous` и `parent-transaction`; выполнить тот же rollback. Не удалять транзакции и не угадывать прежнее состояние. После каждого восстановления проверить корень, оба каталога и глубокие товары, корзину, `/order/`, `/auth/`, CSRF, оплату, robots/sitemap, ресурсы старого браузера и настоящий 404. Цель восстановления — до пяти минут; фактическое время записывается при репетиции.

После rollback `/basket/` через минимальный shim предлагает `/local/tools/o100-cart-recovery.php`. Эта страница сначала проверяет попытку заказа, затем переносит только оставшиеся товары. Неопределённый заказ разрешается по XML_ID и реестру; новый заказ вслепую создавать нельзя. Очковые линзы остаются отдельной заявкой специалисту.

## Наблюдение

Первые 60 минут проверять ошибки API/браузера, заказы, цены, рецепты, запись, корзины и уведомления. В конце дня и следующим рабочим днём сверить операции с сотрудниками и 1С. Дубли, неправильная цена/рецепт, воспроизводимый сбой заказа/записи, авторизации/оплаты или массовая недоступность маршрутов — основание немедленного отката.

Фактические SHA, контрольные суммы, run ID и результаты приёмки записываются в манифест кандидата и журнал backend; пустые поля означают незакрытые ворота, а не подтверждение выпуска.
