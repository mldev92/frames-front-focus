# Выпуск витрины

Ветка `release/storefront` содержит исходник магазина, а `main` — рабочие процессы выпуска. После слияния в ветку витрины GitHub запускает Quality и готовит кандидат для проверенного SHA. Входные данные backend и маршрутизации подготовка читает отдельным SSH-ключом с принудительной командой. При изменении каталога или маршрутов запустите подготовку из `main` с ID проверенного снимка и SHA256 его индекса.

Чтобы опубликовать проверенный кандидат, запустите `Deploy production` из `main` и укажите `candidate_run_id`. SHA и контрольные суммы извлекаются из успешной подготовки. Для отката запустите `Roll back production` из `main` с SHA действующей витрины.

Перед передачей нужны данные квоты аккаунта Beget. Закрытый файл `.o100-deploy/account-capacity.json` рядом с document root должен содержать `measuredAt` (Unix-время замера), `bytes` и `files` (оставшиеся байты и файлы, целые числа). Обновляйте файл атомарно по фактическим данным провайдера. Замер действителен пять минут. При отсутствии данных или нехватке места переключение останавливается. Текущий и резервный выпуски сохраняются.

После переключения проверьте изменённые сценарии при ширине 375 px и на desktop. Следите за ошибками API, ценами, корзиной, заказами и записью в течение первого часа.
