# Рабочий путь production-сборки

Исправление принято PR #2 в `codex/repeat-order-production-20261117`, merge `3e73313c03f3d452e280e2b1cbbc1761f2f01bb8`. Эта ветка основана на фактически работающем frontend; она содержит inventory/fingerprint/packaging и новый проверенный API-снимок. Витрина не перевыпускалась.

`main` существенно старше действующего выпуска и не содержит его инструментов каталога. Частичное копирование snapshot runner создало бы неработоспособную смесь. Поэтому здесь старые build:production, manifest и прямой production Vite прекращаются до сетевых вызовов. Для production выбирать поддерживаемую ветку и её инструкцию `BUILD_API_SNAPSHOT_RU.md`. Workflow capture зарегистрирован на main для обнаружения GitHub, но запускать его нужно с ref поддерживаемой ветки. Подготовка кандидата на main намеренно закрыта.

Quality CI больше не вызывает live beta SSR/загрузку ресурсов; он проверяет локальные зеркала и компилирует с loopback API и запретом внешнего fetch. Полная production-приёмка остаётся отдельным шагом по снимку. Pause/permit 1С блокирует capture; снимать pause ради сборки запрещено. Старые локальные checkout нельзя использовать для выпуска; основной рабочий checkout и старый controller отдельно ограждаются локальными отказами с сохранением исходных файлов.
